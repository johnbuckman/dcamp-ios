## 1. What this is

A **fully native SwiftUI client (iOS 17+)** for **dcamp**, John Buckman's Basecamp-style
forum for the Decent Espresso "Diaspora" community. It replaced an earlier WKWebView
wrapper (that history is in git + NATIVE_PLAN.md; ignore the wrapper approach).

- **This repo**: `~/Documents/dcamp-ios` — the app.
- **The server**: dcamp is NaviServer/Tcl + MySQL + a vanilla-JS SPA living in **`/d`**
  (John's web root, under **CVS**, not git). Backend logic: `/d/lib/dcamp_app.tcl`,
  `/d/lib/dcamp_native.tcl`, `/d/lib/dcamp_push.tcl`. SPA: `/d/support/dcamp/dcamp.js`,
  `dcamp.css`, `index.adp`.
- **Local dev server**: `http://localhost:8000` (already running; John starts it manually).
  Web UI at `http://localhost:8000/dcamp`. Prod is `decentespresso.com/dcamp`.

**The app talks to ONE endpoint**: `POST /support/dcamp/api.adp` with `action=<name>`
form params (~150 actions). Envelope: `{"ok":true,…}` / `{"ok":false,"error":…,"code":…}`.

## 2. Ground rules learned the hard way

- **Never commit without John saying so.** `/d` is CVS and shared with parallel sessions —
  commit ONLY the specific files you touched (`cvs commit <files>`), never a blanket commit.
- **`rtk` wraps shell commands** (token saver). It **mangles `find` in pipelines** (use
  `/usr/bin/find`) and **lies about `cvs status`/`diff`** (use `rtk proxy /usr/local/bin/cvs`
  if output looks wrong).
- The local MySQL DB is a **disposable copy of prod** — safe to write test fixtures into.
- GUI automation (`computer-use`) approval prompts were repeatedly **denied**; verify
  headlessly via the Simulator + `simctl` screenshots (recipe below).

### Server additions (in `/d`, committed to CVS)
- **`lib/dcamp_native.tcl` (rev 1.1, new)** — the native lane:
  - `dcamp_api_tokens` table (lazy `CREATE IF NOT EXISTS`; **not yet in `schema.sql`**).
  - `auth_token(email,pw,device_id,platform)` → mints a 48-char bearer token.
  - **`dcamp_native_apply_bearer`** — THE key bridge. Resolves `Authorization: Bearer <tok>`
    → sets `$::dcamp_uid`, **and synthesizes `email`/`cryptpw` cookies onto the request
    headers** so all cookie-based identity (`dcamp_is_owner` → `can_post`, posting gates)
    works for cookie-less native requests.
  - `token_revoke`.
- **`lib/dcamp_app.tcl`** (hooks added in rev 1.78) — 4 hooks: bearer lane after `$::dcamp_uid`;
  `auth_token` in the pre-login-gate whitelist + in `dcamp_auth_run`; `token_revoke` action;
  `source .../dcamp_native.tcl` at EOF.
- **`lib/dcamp_push.tcl` (1.5)** — real bug fixed: token regex `{32,512}` exceeds **Tcl's 255
  max repetition count** → "invalid repetition count(s)" → *every* APNs `push_register` threw
  (web push path too). Now `{32,}`.

Reload the server after editing `/d` Tcl: **`curl -u <admin-user>:<admin-pw> http://localhost:8000/admin/lib_reload.adp`**
(cvs-free hot reload; `/admin/recvs` also does `cvs up` first). Local `/admin` credentials
are in Claude's private memory / ask John — deliberately not in this repo.

## 4. Gotchas that cost real time (do not rediscover)

1. **Composer send must fetch HTML on demand.** Trix `trix-change` events are unreliable
   through the WKWebView bridge; gating Post/Send on `contentLength` left the button
   permanently disabled ("can't post" bug). `ComposerModel.currentHTML()` reads
   `dcampGetHTML()` at send time. Never re-gate on `contentLength`.
   **1b. The `ComposerModel` MUST be owned as `@State` by the view that hosts the
   `InlineComposer`** (ChatView / DMThreadView / ThreadDetailView all do). `InlineComposer`'s
   `model` default `= ComposerModel()` is recreated on every parent re-render; in a POLLING
   view (chat 3s, DM 6s) that hands the send path a fresh model whose `webView` is nil
   (`ComposerWebView.makeUIView` bound its Coordinator to the *original* model), so
   `currentHTML()` returns an empty fallback and **Send silently no-ops — no send, no error**.
   This was the real "SEND does nothing" bug (v1.8); error-surfacing didn't fix it because
   `onSend` was never reached.
2. **`editor.html` needs `<meta charset="utf-8">`** or placeholders render mojibake ("Writeâ€¦").
3. **`setBadgeCount` pops the notification permission prompt** when status is undetermined —
   `NotificationsStore.updateBadge()` guards on `.authorized`.
4. **SwiftUI `@State` seeded from a parameter only initializes once.** The detail view kept
   showing the first thread until `.id(mid)` was attached. Same class of bug: `has_more` is an
   **Int** (not Bool) — the wrong type silently broke the whole DM decode.
5. **Don't capture a View struct in an escaping poll closure.** Chat/DM polling lives in
   `@Observable` stores; the thread uses a `.task { while … }` loop (MainActor) instead.
6. **`set_cookie` writes a mistyped `:::cookies`**, so `cookie_get`'s `::cookies` fast path is
   dead code — that's why the bearer bridge injects real request headers.
7. **Sheet → navigation race**: pushing while a sheet dismisses is dropped (DM-create bug).
   Push in the sheet's `onDismiss`.
8. **Recursive `@ViewBuilder` can't return `some View`** — use a concrete type (`TrixBlockView`).
9. Simulator: a stuck permission alert survives app reinstall — `simctl erase` clears it.
10. **Never set `.font` on an `AttributedString` run in `Inline`** — a run font overrides the
    view's `.font(…)`, which silently pinned every heading and every screen's 15/16pt body to
    `.body` (v1.19 fix). Use `inlinePresentationIntent` (bold/italic/code/mention) instead.
11. **Trix renderer spacing mirrors the web CSS, not a fixed gap.** Thread/comment bodies have
    `p{margin:0}`, so a blank line is an explicit `<p><br></p>` (→ `.spacer`, one line) — a
    `Text("\n")` is TWO lines tall. A trailing `<br>` adds no line in a browser (trim one "\n"),
    and HTML source whitespace collapses (plain-text bodies with no tags keep their newlines).
    Per-context paragraph gap = `paragraphSpacing` (0 thread/comment, 4 chat, 6 DM, 8 summaries).
12. **Never collapse a block to "its first image".** Trix keeps a post's text AND photos in ONE
    `<div>`; until v1.19 the parser turned any div with an `<img>` into just that image, so most
    image posts lost every word. `splitMixed` now emits text/media blocks in order, `BlockScanner`
    emits loose inline content between blocks as pseudo-`<p>`s (DM/chat bodies are often bare
    `text<br><br>text`), and a wrapper `<div>` takes its BALANCED close + recurses. Regression
    check: run old vs new `TrixParser` over live bodies and compare rendered-word coverage.

## 5. Build / run / verify

```bash
cd ~/Documents/dcamp-ios && xcodegen generate      # after adding ANY file

# Mac Catalyst (what John runs; ad-hoc, push stripped)
printf '<?xml version="1.0"?><!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd"><plist version="1.0"><dict/></plist>' > /tmp/dcamp-local.entitlements
xcodebuild -scheme Dcamp -destination 'platform=macOS,variant=Mac Catalyst' -configuration Debug \
  CODE_SIGN_IDENTITY="-" CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM="" \
  CODE_SIGN_ENTITLEMENTS=/tmp/dcamp-local.entitlements -derivedDataPath build
rm -rf "/Applications/AI Apps/dcamp.app"
cp -R build/Build/Products/Debug-maccatalyst/dcamp.app "/Applications/AI Apps/dcamp.app"

# iOS Simulator (headless verification)
xcodebuild -scheme Dcamp -destination "platform=iOS Simulator,id=$UDID" -configuration Debug \
  -derivedDataPath build-sim CODE_SIGNING_ALLOWED=NO
xcrun simctl install "$UDID" build-sim/Build/Products/Debug-iphonesimulator/dcamp.app
```

**Headless test harness** (DEBUG + env-gated, in `SessionStore.start()` / `MainView.startLive()`) —
pass with the `SIMCTL_CHILD_` prefix:

| Env | Effect |
|---|---|
| `DCAMP_SMOKE_EMAIL` / `_PW` | auto-login (skips the login UI) |
| `DCAMP_SMOKE_MSG` / `_POST` / `_NOTIF` / `_M56` | run API smokes, print results to **stderr** |
| `DCAMP_SHOT_SCREEN` = `board｜thread｜shortthread｜chat｜dms｜dm｜settings｜notifs｜ipadsummary` (`DCAMP_SHOT_THREAD=<id>` picks the thread) | jump straight to a screen **and skip the push prompt** |
| `DCAMP_SHOT_QUERY=<q>` (+ `DCAMP_SHOT_MORE=1`) | with `DCAMP_SHOT_SCREEN=search`: pre-fill the search query (sim text input doesn't register); `_MORE` expands the "Show N more results…" tail after 3s |

```bash
env SIMCTL_CHILD_DCAMP_SMOKE_EMAIL="$TEST_EMAIL" \
    SIMCTL_CHILD_DCAMP_SMOKE_PW="$TEST_PW" \
    SIMCTL_CHILD_DCAMP_SHOT_SCREEN=thread \
    xcrun simctl launch "$UDID" com.decentespresso.dcamp
xcrun simctl io "$UDID" screenshot /tmp/shot.png      # then Read the png
```

**Server (Live/Test) is a runtime toggle**, not a compile-time flag: `AppConfig.useLocalDev`
reads UserDefaults key `dcamp_use_local_dev` (default `false` = Live = decentespresso.com;
`true` = Test = localhost:8000). Admins flip it from **My Settings → Server** (segmented
Live/Test at the top of the form); switching signs you out (OAuth endpoint differs per server)
via `SessionStore.switchServer(local:)`. `Info.plist` has a **dev-only** `NSAllowsLocalNetworking`
for the Test host.

## 8. Commit / deploy / release state

- **This repo**: `github.com/johnbuckman/dcamp-ios` (PUBLIC), branch `main`. Each version is a
  commit that bumps `project.yml` `MARKETING_VERSION` + `CURRENT_PROJECT_VERSION`
  (v1.22 = `15f2c86`, the first Mac release). `git log` / GitHub releases are the version history.
- **Server**: the native lane (`dcamp_native.tcl`, bearer auth, OAuth2 browser sign-in) is LIVE
  on decentespresso.com; the app defaults to Live (§5). Server changes go through `/d` (CVS +
  git mirror) and John deploys them himself via `/admin/recvs`.
- **Release recipe** (unsigned IPA, users re-sign via SideStep/AltStore; plus a notarized Mac
  zip since v1.22):
  1. bump `project.yml` versions → `xcodegen generate` → commit + push.
  2. build from a CLEAN checkout of that commit (`git worktree add --detach <dir> <sha>`) —
     another session may have uncommitted edits in this tree:
     `xcodebuild -scheme Dcamp -sdk iphoneos -configuration Release -derivedDataPath <dd>
     CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO build`
  3. `mkdir Payload && cp -R <dd>/Build/Products/Release-iphoneos/dcamp.app Payload/ &&
     zip -qry dcamp.ipa Payload`; **public repo → scan the binary**:
     `strings Payload/dcamp.app/dcamp | grep -i -E "AuthKey|5XPQQ2VXV8|BEGIN PRIVATE"` (and test creds).
  4. reuse the version-agnostic installer: `gh release download <prev-tag> --repo
     johnbuckman/dcamp-ios --pattern dcamp-installer.zip`.
  5. Mac app (Developer ID, team XLS3XF57J8, notary profile `bping-notary`), same worktree:
     `xcodebuild -scheme Dcamp -destination 'platform=macOS,variant=Mac Catalyst' -configuration Release
     -derivedDataPath <dd-mac> CODE_SIGN_IDENTITY="Developer ID Application: Vid Tadel (XLS3XF57J8)"
     CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=XLS3XF57J8 CODE_SIGN_ENTITLEMENTS=<empty-dict.plist>
     ENABLE_HARDENED_RUNTIME=YES CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO OTHER_CODE_SIGN_FLAGS=--timestamp build`
     (empty entitlements = push stripped, no profile needed). **Without
     `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO` the binary gets `get-task-allow` and notarization is
     Invalid** (fix after the fact: `codesign --force --options runtime --timestamp --entitlements
     <empty-dict.plist> --sign "Developer ID Application: Vid Tadel (XLS3XF57J8)" dcamp.app`). Then
     `ditto -c -k --keepParent dcamp.app dcamp-macos-latest.zip` → `xcrun notarytool submit
     dcamp-macos-latest.zip --keychain-profile bping-notary --wait` (`notarytool log <id>` for issues)
     → `xcrun stapler staple dcamp.app` → re-zip (same name) → verify a quarantined copy with
     `spctl -a -vv -t exec` ("Notarized Developer ID"). Requires macOS 14 (iOS 17 Catalyst).
  6. `gh release create vX.Y dcamp.ipa dcamp-installer.zip dcamp-macos-latest.zip --repo
     johnbuckman/dcamp-ios --target <FULL 40-char sha> --latest --notes-file notes.md` (a short sha
     is rejected). **NOT `--prerelease`** (since v1.22): decentespresso.com/dcamp/help and
     /downloads#dcamp-osx link `releases/latest/download/dcamp-macos-latest.zip`, and
     `/releases/latest/` ignores prereleases — the asset name must stay exactly that.
  7. wait ~1 min, then `gh workflow run "Update app catalog" --repo johnbuckman/SideStep` —
     the SideStep catalog (`sidestep-apps.json`) is BOT-OWNED; never hand-edit it.
